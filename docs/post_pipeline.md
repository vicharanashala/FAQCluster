# Post-Pipeline

The post-pipeline performs a final round of LLM-based deduplication across the FAQ questions generated by the main pipeline, then produces the final deliverable CSV per crop. It runs once per crop after all 7 pipeline stages have completed.

---

## Overview

```
Input:  unique_questions_freq_qa.csv  (Stage 7 output, per crop)
        ↓
  1. Embedding pre-pass (cosine ≥ 0.95 → auto-merge)
  2. Drop PARSE_ERROR / IRRELEVANT_CROP rows
  3. Per-category 2-pass LLM dedup
        ↓
Output: {district}_{crop}.csv         (final deduplicated FAQ)
        {district}_{crop}_review.csv  (human-review file)
```

---

## Deduplication (`post_processing_dedup.py`)

**Entry point:**
```python
deduplicate_and_aggregate(
    input_csv: Path,
    output_csv: Path,
    cancel_event: threading.Event = None,
    ...
)
```

### Step 1 — Drop bad rows
Rows with `Generated_Category` of `PARSE_ERROR` or `IRRELEVANT_CROP` are removed before any dedup logic.

### Step 2 — Embedding pre-pass

```python
embedding_prepass(df, thresh=_EMBED_DEDUP_THRESH)  # default 0.95
```

All `Generated_Question` values are encoded with `paraphrase-multilingual-mpnet-base-v2`. Pairs with cosine similarity ≥ 0.95 are automatically merged — the row with higher `raw_frequency` is kept, and the loser's `raw_frequency` is summed into the winner. This handles near-identical questions that survived the pipeline without any LLM call.

The 0.95 threshold is intentionally strict — only genuinely duplicate phrasings (e.g. "How to control aphids?" / "How do I control aphids?") should auto-merge here.

### Step 3 — Per-category 2-pass LLM dedup

Questions are grouped by `Generated_Category`. Within each category, `_process_category` is called.

#### Pass 1 — Reference scan (parallel)
- For each question: submit `(reference_question, candidate_questions_batch)` to the LLM.
- Prompt: *"Which of the following candidate questions are DUPLICATES of the reference question — meaning a single answer would address both?"*
- Returns a list of indices to merge. Duplicates of the reference are merged into it.
- Batches run in parallel via `ThreadPoolExecutor` with up to 8 workers.

#### Pass 2 — Verification (single call)
- After Pass 1, the surviving questions are sent in one final call: *"Review this list for any remaining duplicates."*
- The LLM returns merge groups; surviving uniques are kept.

#### Cancellation
The `cancel_event: threading.Event` is checked before each batch. If set, the function raises `JobCancelled` immediately.

## Review File Generation (`generate_review_file.py`)

**Entry point:**
```python
generate_review(input_csv: Path, output_csv: Path)
```

Builds a human-review CSV from the deduped FAQ output. The review file is designed for agricultural domain experts to:
- Verify that generated answers are accurate
- Flag questions for follow-up
- Add notes

### Review file columns
| Column | Source |
|--------|--------|
| `rank` | From FAQ |
| `Generated_Category` | From FAQ |
| `Generated_Question` | From FAQ |
| `representative_question` | Original farmer question |
| `sample_questions` | Top phrasings (pipe-separated) |
| `raw_frequency` | How many calls asked this |
| `Generated_Answer` | LLM-generated answer |
| `Reviewer_Notes` | Empty — for human input |
| `Flagged` | Empty — for human input |

## Orchestration

`run_post_pipeline.py` is the orchestrator for the standalone CLI (called by `run_full.py`). The server uses the same logic inline in `_run_post_sync`.

### `run_dedup(input_dir, crops, zwd)`
- Finds subdirectories in `input_dir` matching the given crops.
- For each crop dir: calls `deduplicate_and_aggregate` on `unique_questions_freq_qa.csv`.
- Output written to `{input_dir.name}_{crop_dir.name}.csv`.
- Uploads output to Zoho via `zwd`.

### `run_review(input_dir, crops, zwd)`
- For each deduped CSV just produced: calls `generate_review`.
- Output: `{input_dir.name}_{crop_dir.name}_review.csv`.
- Uploads to Zoho.

### Zoho uploads
After each crop's dedup and review files are written, they are pushed to Zoho at:
```
outputs/repair/<state>/<district>/<crop>/<district>_<crop>.csv
outputs/repair/<state>/<district>/<crop>/<district>_<crop>_review.csv
```
`master.json` is updated: `processed=True`, `output_file=<path>`.
